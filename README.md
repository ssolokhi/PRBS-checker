# PRBS-Checker

Verilog code for measuring bit error rate of *pseudo-random bit sequences* (PRBS). The layout consists of 3 stages:
transmitter, signal transfer, and receiver.

## Transmitter

The transmitter generates a PRBS using a *linear-feedback shift register* (LFSR). At each transmitter clock cycle,
the last bit of the PRBS is sent away from the module. This allows testing serial data transfer, which is more 
relevant for my job.

To ensure that the PRBS has a maximal period ($s^{n_{bits}} - 1$), specific bits of the LFSR are XOR'ed, see 
[Table 2.1 in this article](https://www.physics.otago.ac.nz/reports/electronics/ETR2012-1.pdf).

## Signal Transfer

Currently, the PRBS pattern is sent via internal wiring. See ToDo list.

## Receiver 

The receiving side must compare a sequence of received PRBS bits with the generated PRBS.
Since the generated PRBS is only known to the transmission side, synchronisation is needed.
A local LFSR compares the incoming data with its own output.

The receiver is implemented as a finite state machine with 2 states:

1. **OPEN**: the receiver is trying to understand what pattern was generated at the transmitter side 
2. **LOCKED**: the PRBS pattern is known, the receiver is ready to determine the bit error rate

The transitions exhibit hysteresis behaviour:

1. Transition **OPEN** -> **LOCKED**: **c_LOCK_THRESHOLD** *consecutive* bits must match between the received pattern
and the PRBS generated by the local LFSR
2. Transition **LOCKED** -> **OPEN**: **c_OPEN_THRESHOLD** *consecutive* bits must not match

A signle spurious bit cannot be treated as loss of lock because single errors can exists.
Conversely, the transmission line should not be too bad, so many consecutive errors are more likely
to be due to loss of lock.

## Indication

When the receiver locks onto the PRBS, a green LED lights up. For every error in the transmitted bit pattern, a 
red LED lights up.
